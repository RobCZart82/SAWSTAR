# Preset import latency profile

The manual benchmark times the production import function and UI preparation operations separately. It writes CSV and validates import/skip/failure counts, duplicate counts, retained existing sounds, newly imported sounds, and resulting list sizes. Fixture setup, initial library construction and cleanup are excluded from the clocks.

Build and run (the scratch directory must already exist):

```sh
cmake --build build --config Release --target sawstar_preset_import_benchmark
./build/Release/sawstar_preset_import_benchmark /path/to/scratch 3 > import-profile.csv
```

On macOS use the executable location generated by the selected CMake generator. Repetitions default to 3 and accept 1..20. Each repetition has a fresh, uniquely owned fixture directory. The matrix covers 100/1000 existing presets, 10/100 input files, new sounds, differently named duplicates, name collisions, invalid files, and an empty batch: 54 rows with three repetitions.

Raw [CSV](measurements/preset-import-windows-2026-10-07.csv) and [provenance/hash manifest](measurements/preset-import-windows-2026-10-07.json) are retained. CPU model was unavailable. These are measurements on one local filesystem with setup-warmed caches, not cold-cache, external/network-volume or native host acceptance. No competing writer, GUI rendering, dialogs or audio callback is timed. The quick-list phase includes directory enumeration and sorting for the selector; it is a separate action and must not be added to the import callback's duration.

In this fixture, import dominates the subsequent browser refresh/filter/preview. New sounds need duplicate comparison against the existing library before durable writes. The duplicate batch can also decode much of the sorted library; the measured duration alone does not isolate decoding from other I/O. Do not infer an audio dropout from these numbers.

## Next implementation gate

Move batch import and its I/O off the GUI thread with an owned job/result lifecycle. Retain the current cross-instance mutation lock, exclusive writes, exact duplicate/collision results and error reporting. Apply completed results and show dialogs only on the GUI thread. Closing/reopening the editor or unloading the plugin must not leave a worker accessing GUI/plugin objects. Profile completion refresh separately; ordinary Save/Rename/Delete must also be checked when an import job holds the mutation lock.

This measurement change does not itself make the production import asynchronous or establish native REAPER acceptance.
